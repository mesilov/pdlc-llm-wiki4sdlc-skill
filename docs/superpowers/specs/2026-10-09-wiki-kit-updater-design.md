# Проверка и обновление установленного wiki-набора

Запрос: [issue #7](https://github.com/mesilov/pdlc-llm-wiki4sdlc-skill/issues/7).
Статус: согласовано пользователем 2026-10-09; поручена реализация в отдельном worktree.
Milestone: 0.1.0.

## Выбор подхода

Superpowers и mattpocock/skills используют менеджеры плагинов; mattpocock/skills
также распространяется через skills CLI с lock-файлом источника/ref/хеша.
Сохраняем стандартный формат Agent Skills. Собственный updater обслуживает
полную установку навыков вместе с отдельным CLI; публикация marketplace
или плагина не входит в этот issue.

Рекомендуется устанавливаемый Python CLI со стандартной библиотекой и GitHub
REST API. Он работает прямо в целевом проекте, без сохранённого checkout набора.
Проверка только GitHub Releases не обнаруживает изменения между релизами.
Обновление через локальный git clone требует Git и отдельного рабочего каталога.
Поэтому CLI поддерживает main и release, скачивая архив точного commit SHA.

## Поведение для пользователя

- `bin/wiki/update --check`: read-only проверка, текущая и доступная revision,
  канал, ссылка на сравнение или release, предложение команды обновления.
- `bin/wiki/update`: проверка, предложение обновления и запись после ответа да.
  В неинтерактивном режиме выводит предложение, не читает stdin и не пишет.
- `bin/wiki/update --force`: без подтверждения устанавливает выбранную revision,
  даже если она уже установлена. Локальные правки управляемых файлов сохраняет
  в backup перед заменой. Остальные файлы проекта не входят в scope.
- `--channel main|release`: main по умолчанию; установленный канал сохраняется.
  Release использует последний опубликованный стабильный GitHub Release.
  Отсутствие release не превращается в молчаливое обновление из main.
- `--json`: машинный результат проверки; только вместе с `--check`.
- `python3 scripts/update.py /path/to/project`: тот же CLI из свежего checkout
  для старой установки, где команда и manifest ещё отсутствуют.

Коды: 0 — обновление выполнено или изменений нет; 1 — обновление предложено,
но не выполнено; 2 — ошибка сети, конфликта, комплекта или аргументов.

## Учёт установленного комплекта

Отдельный `skill-version.json`: версия схемы manifest, GitHub repository, канал,
commit, tag/version при наличии, признак локально изменённого источника,
SHA-256 каждого управляемого файла. Manifest не является профилем wiki.
Установщик записывает его после установки; повторная идентичная установка
не меняет mtime. Для checkout без Git или с незакоммиченными ресурсами
происхождение не выдаётся за подтверждённый upstream snapshot.

Управляемые ресурсы: восемь `.agents/skills/wiki-*` целиком и `bin/wiki`.
Корпус, `wiki.config.json`, проектные инструкции, CI и чужие файлы сохраняются.
Существующие aliases продолжают ссылаться на канонические каталоги навыков.

## Получение обновления

GitHub API разрешает main или release tag в SHA; архив запрашивается по SHA,
чтобы смена ветки между проверкой и загрузкой не меняла устанавливаемую revision.
Чужие scripts/install.py из архива не исполняются. Состав комплекта проверяет
локальный код. При извлечении разрешены только обычные файлы ресурсов набора;
symlinks, traversal и неполный комплект отклоняются до изменения проекта.

## Замена файлов

План строится целиком до записи. Без force локально изменённые файлы и
конфликтующие новые пути блокируют весь update. С force изменённые файлы
копируются в `.wiki-kit-backups/` вместе с прежним manifest. Старые ресурсы
удаляются только по manifest; неизвестные файлы остаются на месте.
Symlinks не заменяются даже с force. Ошибка записи требует восстановления
прежних файлов; новая revision записывается в manifest последней.

В старой установке без manifest версия неизвестна. Check сообщает это явно.
Для bootstrap доступны обычное обновление совпадающих файлов и force с backup
отличающихся известных ресурсов; неизвестные старые файлы не удаляются.

## Как пользователь узнаёт об обновлении

Общий контракт восьми навыков предписывает один read-only check в начале
сессии, если установлен updater и сеть разрешена. При новом состоянии агент
показывает текущую и доступную revision и предлагает обновить комплект.
Он не запускает update или force сам по результату проверки.
Ошибка сети сообщается кратко и не блокирует основную wiki-задачу.
Нет фонового расписания, обязательного сервиса или сетевой проверки в lint/status.

## Проверки

Unit/integration tests на временных проектах: main update, major release,
отсутствие release и сети, одинаковая revision, check без записи, отказ,
force без stdin, bootstrap, локальные конфликты и backup, сохранение профиля,
корпуса и неизвестных файлов, удаление старого ресурса, symlinks/traversal,
неполный архив, ошибка записи и rollback. Полный unittest suite, whitespace
новых файлов, валидатор навыков и установленный CLI.

GitHub main пока не содержит updater: живая проверка API возможна отдельно;
end-to-end сценарии обновления проверяются на воспроизводимых архивах фикстур.
