# Wiki Self-Diagnostics Implementation Plan

**Goal:** Добавить самодиагностику OpenSpec CLI/skills для Codex, Claude Code и OpenCode и путей wiki-профиля.

**Architecture:** `bin/wiki/doctor` вызывает отдельный `_doctor.py` и общий валидатор `wiki_layout`. Поиск корня умеет вернуть границу checkout до валидации, чтобы неверный профиль не скрывал диагностику окружения. Установщик переносит команду вместе с комплектом.

**Tech Stack:** Python 3.10+, стандартная библиотека, unittest; новых зависимостей нет.

## Контракт

- Только чтение; без установки, исправления конфига, вызова init/update и записи bytecode.
- `--project PATH` задаёт целевой проект; без него используется текущий checkout, включая вложенный cwd и Git worktree с `.git`-файлом.
- `--tools codex,claude,opencode` выбирает агентов; по умолчанию проверяются все три.
- Проверяются существующие локальные и пользовательские каталоги skills. Для Codex поддерживается legacy `.codex/skills`; для OpenCode также `.agents/skills` и `.claude/skills`.
- Каждый найденный `openspec-*` проверяется на читаемый SKILL.md, минимальные name/description и непустое тело. Отчёт показывает пути поиска; полный YAML/семантика и загрузка в активную сессию не проверяются.
- Нет фиксированного количества skills: OpenSpec допускает разные workflow profiles. Наличие хотя бы одного корректного навыка не доказывает полноту профиля.
- CLI ищется в PATH, вызывается только `openspec --version` без shell с положительным таймаутом; сообщаются путь, версия и ошибка запуска.
- Общий профиль сохраняет существующие правила безопасности. Doctor дополнительно проверяет типы путей и наличие roots/schema/index; необязательные документы и scan_files при отсутствии дают warning, выключенные документы и ещё не созданные layers — skip.
- OpenSpec остаётся opt-in: при выключенном `openspec_root` отсутствие CLI/skills даёт warning; при подключении либо `--require-openspec` — error. Строгий режим также требует явно подключённый каталог.
- JSON содержит project/tools/checks/summary/exit_code; коды: 0 без ошибок (warnings допустимы), 1 проблемы готовности, 2 неверный вызов/профиль/корень.
- Успех не доказывает смысл спецификации, реализацию, runtime или разрешения и фактическую загрузку skills агентом.
