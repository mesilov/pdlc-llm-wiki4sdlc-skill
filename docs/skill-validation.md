# Проверка переносимости — 2026-10-05

## Исходная версия

На перенесённом, ещё не адаптированном CLI запущены новые сценарии профиля.
Шесть ожидаемых failures показали: обязательный OpenSpec блокирует четыре
команды; независимые raw/knowledge и переименованные supporting файлы не
поддерживаются; свой naming convention решений и выключенный glossary
не поддерживаются.

Независимый агент прочитал исходные восемь skills и общий контракт и применил
их к лаборатории с docs/evidence, docs/wiki, navigation.md, terms.md и без
OpenSpec. Все восемь операций были заблокированы исходными предусловиями.
Он также выявил требование переносить CLI вместе с общим ресурсом.

## Адаптированная версия

Повторная независимая проверка того же сценария использовала только новый
комплект и профиль лаборатории: language=en, domains=topics, decisions=adr,
имя ADR-[0-9]+.md и статусы draft/approved/replaced с пояснениями в schema.

| Операция | Проверенный результат инструкций |
| --- | --- |
| query | Реальные пути из профиля; ответ на английском; без записи или log |
| ingest | Новый snapshot; сохранение старого evidence и contradiction |
| research | Даты/region/plan для pricing; ответ в canonical topic |
| update | Affected + semantic search; только реальные downstream implications |
| audit | Проверка claims и источников; report-only не записывает wiki |
| lint | terms.md вместо GLOSSARY.md; значение отделено от применения |
| merge | Уникальное знание, conflicts и inbound links сохраняются |
| decide | ADR record со статусом draft; отсутствие формализации явно указано |

OpenSpec null не блокирует ни одну процедуру. CI, публикация и реализация
не возникают из выполнения wiki workflow. По этой проверке реальных
противоречий в инструкциях не найдено. Это сценарная проверка принятия
решений по тексту, а не свидетельство выполнения восьми продуктовых задач.

## Исполняемые проверки

`python3 -m unittest discover -s tests -t .` — 71 tests, OK.

- Механика Markdown links, escapes/symlinks, duplicates, orphans и index.
- Glossary: сохранение блоков/определений/команд, сортировка, idempotence.
- Профиль: независимые и перемещённые корни, отключённый/подключённый OpenSpec,
  отключённый glossary, custom ADR filenames, неверные поля/типы/пути.
- Установка в временные проекты: dry-run без записи; preflight конфликта;
  отказ от symlinks; повторная установка без записи; сохранение существующего
  профиля; запуск всех четырёх CLI без OpenSpec.
- Перемещение самого комплекта в другой каталог и установка оттуда; отказ
  до записи при отсутствии обязательного CLI, контракта, профиля или шаблона.
- Все восемь entrypoints, UI metadata, относительные ссылки и отсутствие
  путей/политики исходного проекта в runtime resources.

`skill-creator/scripts/quick_validate.py` недоступен в текущем окружении из-за
отсутствия PyYAML. Требования к простому frontmatter и ссылкам проверены
независимыми stdlib tests; шаблонных placeholders нет. Это не создаёт
pip-зависимость для установленного набора.

Финальное независимое ревью выявило пропуск: неполный исходный комплект
мог устанавливать неработающий CLI с exit 0. Воспроизведение подтверждено;
preflight обязательных ресурсов добавлен и проверен regression test.
Других воспроизведённых ошибок переноса или изменения чужих файлов ревью не нашло.

Внешние источники, CI, публикация и runtime продуктовых проектов в этих
проверках не использовались.

## Общий глоссарий и синонимы — 2026-10-05

До изменения общий формат синонимов отсутствовал: независимая сценарная
проверка выбрала безопасную запись с поясняющим текстом, но отметила, что
различие допустимых и неоднозначных названий остаётся на усмотрение агента.

После изменения другой агент прочитал подключённый glossary.md и повторил
сценарий с knowledge_root=docs/wiki, glossary=terms.md и openspec_root=null.
Подтверждённые интервью названия «Reservation» и «резервирование» попали
в «Синонимы» с ограничением контекста; многозначная «бронь» — в «Избегать»
с причиной. Резерв товара и бронирование слота остались разными понятиями.
Query не разрешил запись; отключённый glossary и report-only lint не привели
к созданию файла или журналированию. Это проверка решений по инструкциям,
а не выполнение операций в продуктовом проекте.

`python3 -m unittest discover -s tests -t .` — 72 tests, OK.
Установка выполнялась только во временные проекты. Проверено копирование
glossary.md и отказ до записи при его отсутствии; новый regression test
сначала воспроизвёл установку неполного комплекта с exit 0, затем прошёл.
Существующая проверка сортировки дополнена полями «Синонимы», «Избегать»
и «Контекст»: содержание записей и idempotence сохраняются.

Ссылки и frontmatter проверены stdlib package tests. PyYAML по-прежнему
недоступен, поэтому quick_validate.py отдельно не запускался.
`git diff --check` и проверка всех новых файлов относительно `/dev/null`
не нашли whitespace-проблем.

## Первоначальная адаптация технического письма по УТР — 2026-10-06

Проверки ниже относятся к сокращённой версии до полного переноса исходника.

До изменения независимый агент прочитал текущие contract.md, glossary.md
и wiki-update. В сценарии редактирования гипотезы первое предложение содержало
21 слово. В регламенте два последовательных действия остались в одном
предложении, а условие запуска миграции стояло после команды. Агент отметил,
что обязательных числовых пределов и формы глаголов набор не задаёт.
Статус гипотезы, неизвестный эффект и технические строки были сохранены.

После изменения writing.md подключён обязательным чтением из контракта
для всех wiki-* и отдельным шагом смысловой проверки wiki-lint.
Каталог содержит 25 строк требований с номерами пунктов, правила сохранения
смысла, редакционные замены и восемь шагов самопроверки.
Новые поля профиля, русский язык по умолчанию и внешние зависимости не добавлены.

Другой агент повторил те же два сценария, читая только установленный набор
во временном проекте. Самое длинное предложение описания содержало 19 слов;
два описательных абзаца содержали четыре и три предложения. Команды регламента
разделены, условие стоит перед запуском миграции. Сохранены основание гипотезы,

Агент правильно отделил русский каталог от language=en и сохранил запрет

Проверка выявила два уточнения: подсчёт числа с единицей измерения и точной

уточнено. Повторный сценарий в свежей установке сохранил «Валидируйте JSON»
и «Проверьте доступность сервера» как разные команды. Одиночное причастие
«выявленные» осталось допустимым. Предложение «После ответа
`HTTP 429: Too Many Requests` подождите 60 секунд» содержит пять единиц подсчёта.
Происхождение и пределы сверки источника доступны в установленном writing.md.

Это проверка поведения по инструкциям на ограниченных сценариях, а не
доказательство соответствия ГОСТу или выполнения продуктовых процедур.

## Полный перенос исходного навыка УТР — 2026-10-06

После уточнения пользователя сокращённая адаптация заменена точными копиями
SKILL.md, checklist.md, use-cases.md и before-after-ru.md исходного русского навыка.
Дополнительно перенесены связанный английский пример, исходный линтер,
его локальная зависимость и лицензия. Wiki-границы перечислены отдельно

Два новых regression tests сначала завершились ошибками: отсутствовал manifest,
а установщик принимал комплект без исходных ресурсов. После реализации
проверены SHA-256 восьми файлов, их набор и pinned commit.
Отсутствие каждого из восьми ресурсов или manifest останавливает установку
до первой записи. Тест установки сравнивает все перенесённые файлы побайтово.
Общие проверки ссылок подтверждают доступность связанного английского примера.

В отдельном временном проекте установлен полный набор. Локальный
`utr_lint.py --self-test` завершился успешно: 25 эвристических нарушений
в контрольном «водяном» тексте и 0 в чистом тексте; проверки разбиения прошли.
Это встроенная проверка счётчика, а не новый benchmark моделей или доказательство соответствия ГОСТу.

В отдельной поведенческой проверке агент прочитал только установленный набор,
включая полный каталог, чек-лист, области применения и примеры. Три сценария

Строгий режим при отсутствии базы не разрешил сменить язык, профиль или создать глоссарий.
Противоречия механического поиска, примеров с двумя командами и словаря замен
