# PDLC LLM Wiki Skills

Автономный набор из восьми `wiki-*` для работы с Git-native wiki:
первичные материалы → каноническое знание → решения → спецификация →
проверка реализации. Происхождение, противоречия и неизвестные сохраняются
на каждом этапе. Набор переносится между проектами; предметные данные,
правила веток и публикации задаются целевым проектом.

| Skill | Когда применять | Изменяет состояние wiki |
| --- | --- | --- |
| [wiki-query](skills/wiki-query/SKILL.md) | Ответ по существующим знаниям без записи | Нет |
| [wiki-ingest](skills/wiki-ingest/SKILL.md) | Новый источник, наблюдение или идея | Да |
| [wiki-research](skills/wiki-research/SKILL.md) | Исследование вопроса с новыми источниками | Да |
| [wiki-update](skills/wiki-update/SKILL.md) | Каскадное обновление из уже имеющихся оснований | Да |
| [wiki-decide](skills/wiki-decide/SKILL.md) | Предложение или запись осознанного выбора | Да |
| [wiki-audit](skills/wiki-audit/SKILL.md) | Проверка поддержки claims источниками и свежести | Нет в report-only; да при разрешённых исправлениях |
| [wiki-merge](skills/wiki-merge/SKILL.md) | Объединение или разделение страниц без потери знания | Да |
| [wiki-lint](skills/wiki-lint/SKILL.md) | Механическая и смысловая проверка wiki, включая термины | Нет в dry-run; да в fix |

Состояние wiki включает первичные материалы, страницы знаний, решения,
глоссарий, навигацию и журнал. Отметка «Да» означает запись в рамках
запрошенной операции; она не разрешает commit или публикацию.

`ingest` начинается с уже поступившего материала: например, «вот интервью,
занеси его в wiki». Он сохраняет материал, сопоставляет его с текущими знаниями
и обновляет затронутые страницы. `research` начинается с вопроса: например,
«какие проблемы пользователей подтверждаются исследованиями?». Он ищет и
сравнивает источники, формирует ответ и сохраняет результат в wiki.
Оба скилла могут добавлять evidence и менять каноническое знание.

## Установка в проект

Нужен Python 3.10+; CLI использует только стандартную библиотеку. Сетевые
сервисы, API keys, pip-зависимости и OpenSpec для обычной wiki не требуются.
Для исследования агенту нужен доступ к источникам; при отсутствии доступа
он сообщает конкретное ограничение, а не придумывает evidence.

В клонированном checkout этого набора выполните:

```bash
# Сначала посмотреть список файлов и проверить конфликты.
python3 scripts/install.py /path/to/project --init-wiki --dry-run

# Установить восемь skills, CLI и нейтральную wiki.
python3 scripts/install.py /path/to/project --init-wiki

# Для Claude Code можно также добавить относительные aliases.
python3 scripts/install.py /path/to/project --claude
```

Скрипт копирует `skills/wiki-*` в `.agents/skills/`, CLI в `bin/wiki/`.
`--init-wiki` добавляет [шаблон](templates/wiki/knowledge/SCHEMA.md) raw/knowledge
и wiki.config.json. Он рассчитан на новую wiki: для существующей используйте
установку **без** `--init-wiki` и настройте профиль по реальным путям.
Каталог назначения должен существовать.

До записи проверяются все конфликты. Отличающиеся существующие файлы и symlinks
в пути назначения отклоняются; одинаковые файлы пропускаются без записи.
Обновление локально изменённой установки требует явного сравнения/переноса правок.
AGENTS.md, репозиторий Git, CI и существующий корпус скрипт не изменяет.

Настройте имя/контекст/язык в `wiki.config.json`. Инструкции скиллов написаны
по-русски; язык знаний и ответов задаётся проектом или запросом.
Откройте [профиль и полный список параметров](skills/wiki-query/references/profile.md).
Пути raw/knowledge, имена supporting файлов и слоёв, формат ADR, статусы,
порядок glossary и views настраиваются. OpenSpec отключён по умолчанию;
для подключения существующей интеграции укажите openspec_root.

В AGENTS.md целевого проекта можно добавить:

```markdown
Для wiki используй локальные wiki-* из .agents/skills.
Прочитай wiki.config.json и общий контракт wiki-query/references/contract.md.
Пути в skills — логические обозначения; разрешай их через профиль.
Query и report-only audit/lint ничего не записывают.
После изменения знаний выполняй wiki-lint fix в scope задачи.
Правила принятия решений, спецификации, Git, CI и публикации заданы этим проектом.
```

Устанавливайте восемь скиллов как комплект: общий контракт находится внутри
wiki-query, остальные ссылаются на него и wiki-lint.
[Общие правила глоссария](skills/wiki-query/references/glossary.md) задают
формат, канонические названия, синонимы и названия, которых следует избегать;
wiki-lint выполняет их смысловую проверку. Можно перенести комплект
вручную, сохранив соседство каталогов и bin/wiki. Код не обращается к исходному
checkout и не зависит от пользовательской памяти.

[Правила технического письма](skills/wiki-query/references/writing.md)
усиливают все восемь навыков полным русским навыком SimpleEn-RU по ГОСТ Р 58049-2017.
ГОСТ посвящён переводу эксплуатационной документации на изделия авиационной
техники с/на иностранные языки. Раздел 8.2 задаёт правила упрощённого технического
русского языка: они помогают уменьшить неоднозначность исходного текста
и подготовить его к переводу. В набор включены без сокращений
[исходный SKILL.md](skills/wiki-query/references/utr-source/skills/simple-russian/SKILL.source.md),
[полный чек-лист](skills/wiki-query/references/utr-source/skills/simple-russian/references/checklist.md),
[области применения](skills/wiki-query/references/utr-source/skills/simple-russian/references/use-cases.md)
и [шесть развёрнутых примеров](skills/wiki-query/references/utr-source/examples/before-after-ru.md).
Это пересказ ГОСТа автором навыка, а не официальный текст стандарта.
Для русского авторского текста заданы предел 20 слов в предложении,
размер описательного абзаца, грамматика инструкций, порядок условий и предупреждений.
Терминология сверяется с глоссарием; условия, неопределённость и виды знания сохраняются.
Правила читаются через общий контракт и проверяются агентом перед сдачей.
Все wiki-ограничения и отступления перечислены отдельно в writing.md.
Исходные файлы сохранены побайтово с MIT-лицензией и SHA-256;
доступен необязательный исходный линтер на стандартной библиотеке Python.
Внешний SimpleEn-RU устанавливать не требуется. CLI wiki не проверяет грамматику
и не подтверждает соответствие стандарту. Происхождение описано
в [provenance](docs/provenance.md), прежние отклонения —
в [аудите переноса](docs/utr-transfer-audit.md).

## Проверки в целевом проекте

Из корня установленного проекта:

```bash
bin/wiki/lint --dry-run
bin/wiki/status
bin/wiki/find-orphans
bin/wiki/affected 'понятие или путь'
# После разрешённой правки: только сортировка H2-блоков glossary + проверка.
bin/wiki/lint --fix
```

Коды lint: 0 — нет blocking errors, 1 — errors, 2 — ошибка вызова/профиля.
Warnings не меняют exit code. `--fix` не пишет определения, не выбирает верную
сторону противоречия, не меняет статус решений и не заменяет semantic review.
Проверка links не проверяет HTTP availability, anchors или смысл требования.
Affected даёт кандидатов по links/тексту; полнота воздействия проверяется агентом.

## Проверки самого набора

В корне этого репозитория нет рабочего корпуса проекта; bin/wiki проверяется
на временных независимых wiki. Все тесты запускаются одной командой:

```bash
python3 -m unittest discover -s tests -t .
```

Проверяются links и небезопасные пути, glossary preservation/idempotence,
профиль, OpenSpec, установка, конфликты и перенос полного комплекта.
См. [происхождение](docs/provenance.md) и [сценарии проверки навыков](docs/skill-validation.md).
