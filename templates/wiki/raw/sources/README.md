# Исходные материалы

Храните здесь документы, снимки источников, интервью, скриншоты, наблюдения,
логи, измерения и результаты проверок. Название категории не подтверждает достоверность материала.
Различайте заявление источника, прямое наблюдение и результат проверки в описании единицы.

Новая единица имеет путь `<тема>/YYYY-MM-DD-<название>/README.md`.
Дата обозначает получение материала; тема и название используют lowercase-kebab-case.
Даже один исходный файл получает папку с корневым README.md.
Храните оригиналы рядом без изменения формата; подпапки создавайте по содержимому.

Корневой README.md — UTF-8 Markdown с YAML frontmatter по форме OKF v0.2.
Минимум: `type: Source material`, непустые `title`, `description` и список `sources`.
У каждого основания есть стабильный `id` и `resource`: реальный URL или локальный путь.
Пустой список допускается с объяснением отсутствующего основания.
В тексте укажите происхождение, дату получения, известные версию и дату публикации,
метод наблюдения или проверки, контекст, ссылки на файлы и ограничения.
Неизвестное отметьте явно; события `verified` требуют фактической проверки указанной области и версии.

Перед созданием проверьте совпадения по происхождению, версии, содержанию и контексту.
Для нового снимка создайте новую единицу; не заменяйте старый.
При совпадении даты и названия добавьте суффикс версии или контекста.

Канонический синтез хранится в knowledge/domains по профилю проекта.
Прежние материалы не мигрируют автоматически; явная схема проекта имеет приоритет.
Полные правила находятся в references/raw.md установленного wiki-query.
После создания или изменения единицы выполните `bin/wiki/raw-lint <unit-path> --json`.
Команда проверяет структуру, а смысл и область подтверждения проверяет агент.

См. [общую структуру raw](../README.md) и [схему wiki](../../knowledge/SCHEMA.md).
