# Схема знаний проекта

`wiki.config.json` определяет пути и соглашения. Отсутствующее поле использует
дефолт набора. Имя и язык проекта задаются профилем; scope и правила поставки —
инструкциями пользователя и AGENTS.md целевого проекта.

| Слой | Назначение |
| --- | --- |
| raw | Первичные материалы с provenance, датой, версией и контекстом |
| domains | Канонический синтез по понятиям и предметным областям |
| views | Производные представления знаний по вопросам жизненного цикла продукта |
| decisions | Осознанный выбор со статусом, владельцем и evidence |
| inbox | Идеи, которые пока не являются фактами или решениями |
| archive | Исторические страницы с явной ссылкой на замену |

Каталоги domains/views/decisions/inbox/archive создаются по необходимости.
Явный `views` профиля заменяет дефолтную карту; цели и расположение страниц
описываются этой схемой и индексом. Без поля и специальной карты применяются
этапы pDLC (Product Development Life Cycle):

| Этап / view | Цель |
| --- | --- |
| Ideation / `ideation` | Найти возможности и сформулировать идеи |
| Discovery / `discovery` | Понять пользователей, проблему, рынок и альтернативы |
| Definition / `definition` | Определить задачу, границы и критерии успеха |
| Design / `design` | Спроектировать решение: UX, сценарии, архитектуру и контракты |
| Development / `development` | Реализовать согласованное решение |
| Validation / `validation` | Проверить качество и достижение критериев успеха |
| Launch / `launch` | Доставить продукт пользователям и обеспечить запуск |
| Optimization / `optimization` | Улучшать работающий продукт по данным и обратной связи |

Этапы повторяются и пересекаются. Views — вопросы к каноническим знаниям,
а не обязательные каталоги или статусы продукта. Выбирайте основное view по
цели материала и дополнительные по реальному влиянию. Факты остаются на
предметных страницах; views связываются с ними ссылками. Не создавайте пустые
страницы ради классификации. `views: []` отключает дефолтную карту.

Глоссарий содержит H2-записи с каноническим названием, кратким определением
и относительной ссылкой на контекст. По необходимости добавляется `_Avoid_`:
нежелательные альтернативные названия и синонимы с причиной. Отдельного списка
допустимых синонимов нет. В новых объяснениях используется каноническое название;
варианты из `_Avoid_` помогают искать старые употребления. Синонимы одного
понятия не требуют отдельных записей; одинаковое слово для разных понятий
не делает их синонимами.
Условия применения, лимиты и реализация остаются на профильных страницах.
Статусы решения по умолчанию: proposed, accepted, rejected,
superseded. Имя файла по умолчанию: YYYY-MM-lowercase-kebab-case.md.

Факт, предположение, решение, спецификация, реализация и проверка в runtime —
разные уровни подтверждения. Сохраняйте противоречия и неизвестные явно.
OpenSpec подключается только явным openspec_root; обычное обновление знаний
не создаёт спецификацию и не подтверждает реализацию.
