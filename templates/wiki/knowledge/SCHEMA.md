# Схема знаний проекта

`wiki.config.json` определяет пути и соглашения. Отсутствующее поле использует
дефолт набора. Имя и язык проекта задаются профилем; scope и правила поставки —
инструкциями пользователя и AGENTS.md целевого проекта.

| Слой | Назначение |
| --- | --- |
| raw | Первичные материалы с provenance, датой, версией и контекстом |
| domains | Канонический синтез по понятиям и предметным областям |
| views | Производные представления знаний по вопросам жизненного цикла продукта |
| decisions | Осознанный выбор со статусом, владельцем и evidence |
| inbox | Идеи, которые пока не являются фактами или решениями |
| archive | Исторические страницы с явной ссылкой на замену |

Каталоги domains/views/decisions/inbox/archive создаются по необходимости.
Карта views задаётся этой схемой и индексом. Стартовые вопросы: product,
discovery, experience, engineering, go-to-market, operations, measurement.
Не создавайте пустые страницы ради этой классификации.

Глоссарий содержит H2-записи с каноническим названием, кратким определением
и относительной ссылкой на контекст. По необходимости добавляются «Синонимы»
(подтверждённые альтернативы, переводы и сокращения) и «Избегать» (неоднозначные
или устаревшие названия с причиной). Синонимы одного понятия не требуют
отдельных записей; одинаковое слово для разных понятий не делает их синонимами.
Условия применения, лимиты и реализация остаются на профильных страницах.
Статусы решения по умолчанию: proposed, accepted, rejected,
superseded. Имя файла по умолчанию: YYYY-MM-lowercase-kebab-case.md.

Факт, предположение, решение, спецификация, реализация и проверка в runtime —
разные уровни подтверждения. Сохраняйте противоречия и неизвестные явно.
OpenSpec подключается только явным openspec_root; обычное обновление знаний
не создаёт спецификацию и не подтверждает реализацию.

См. [индекс](index.md), [обзор](synthesis.md), [глоссарий](GLOSSARY.md),
[предположения](ASSUMPTIONS.md), [вопросы](OPEN-QUESTIONS.md) и [журнал](log.md).
