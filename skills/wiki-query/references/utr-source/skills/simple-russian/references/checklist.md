# Проверочный лист

Выполняйте этот проход по каждому черновику перед сдачей. Проверки идут от механических к смысловым. Номера пунктов — по ГОСТ Р 58049-2017.

## Механические проверки (по поиску)

Ищите каждый образец в черновике. Каждое попадание вне блоков кода и цитируемого текста — нарушение.

| Ищите | Нарушение | Как исправить |
|---|---|---|
| `ющ`, `ущ`, `ащ`, `ящ`, `вш` | Причастие (8.2.3.11) | Придаточное со словом «который» или одиночное причастие перед существительным. |
| `нн` + окончание прилагательного | Страдательное причастие (8.2.3.11) | Замените глаголом в личной форме. |
| `вши`, `вшись`, `-ая`/`-яя` перед запятой | Деепричастие (8.2.3.11) | Отдельное предложение с союзом «затем» или «потому что». |
| `является`, `представляет собой` | Номинативная связка (8.2.3.10) | Тире или глагол действия. |
| `осуществля`, `производится`, `выполняется` | Отглагольная конструкция, страдательный залог (8.2.3.10, 8.2.3.13) | Глагол действия с подлежащим. |
| `должен быть`, `должна быть`, `должны быть` | Составное сказуемое, страдательный залог (8.2.3.11, 8.2.3.13) | Повелительное наклонение. |
| `необходимо`, `следует`, `нужно`, `требуется` + инфинитив | Не повелительное наклонение (8.2.3.9) | «Установите», «Запустите». |
| Пункт списка, начинающийся с инфинитива | Инфинитив вместо команды (8.2.5.3) | Повелительное наклонение множественного числа. |
| `нажми`, `проверь`, `настрой` | Единственное число (8.2.3.9) | Множественное число: «нажмите». |
| `если`, `когда`, `в случае` в середине предложения | Условие после команды (8.2.7) | Перенесите условие в начало, поставьте запятую. |
| `кнопк`, `ссылк` | Слова интерфейса (8.2.3.18) | «Узнайте больше [гиперссылка]». |
| `и т. д.`, `и т. п.`, `и пр.` | Сокращение вместо перечня (8.2.3.15) | Назовите элементы. |
| `просто`, `легко`, `мощный`, `надежный`, `современный` | Вода без факта | Удалите. |
| `фиксить`, `дропнуть`, `чекнуть`, `юзать` | Заимствование при наличии русского слова (8.2.3.6) | «Исправить», «удалить», «проверить», «использовать». |
| `из коробки`, `под капотом`, `в два клика` | Метафора или жаргон (8.2.3.5) | «По умолчанию», «внутри», опишите шаги. |

## Счетные проверки

1. **Длина предложения.** Посчитайте слова в каждом предложении. Предел — 20 слов и для инструкции, и для описательной части (8.2.5.1, 8.2.6.1).
   Одним словом считаются: команда в обратных кавычках, числовое значение, аббревиатура, буквенно-цифровой идентификатор, название, цитируемый текст.
   Текст в скобках считается отдельным предложением, и предел 20 слов действует на него тоже.
2. **Размер абзаца.** Максимум шесть предложений (8.2.6.2). Абзац из одного предложения — не чаще одного раза на каждые 10 абзацев.
3. **Цепочки существительных.** Три и более существительных подряд запрещены (8.2.3.10). Разрывайте предлогом или заменяйте глаголом.
4. **Команд в предложении.** Одна, кроме случая одновременных действий (8.2.5.2).

## Смысловые проверки

5. **Тип текста.** Каждый фрагмент — либо инструкция, либо описательная часть. В инструкции повелительное наклонение множественного числа, в описании его нет.
6. **Порядок слов.** Прямой. Подлежащее не в конце простого предложения, прямое дополнение не перед сказуемым (8.2.3.4).
7. **Залог.** В инструкциях страдательного залога нет (8.2.3.13). В описании допустимы неопределенно-личные и безличные конструкции (8.2.3.3).
8. **Место условия.** Каждое «если» стоит перед своей командой, через запятую (8.2.7).
9. **Единообразие терминов.** Один термин на одно понятие во всем документе (8.2.3.7). Проверьте наборы: проверить / убедиться / удостовериться, настройки / конфигурация / параметры, запустить / выполнить / вызвать.
10. **Предупреждения.** Сначала команда или условие, потом риск (8.2.7).
11. **Полнота.** Опущения и сокращения, искажающие смысл, отсутствуют (8.2.3.15).
12. **Неприкасаемое цело.** Код, идентификаторы, цитируемые ошибки и названия продуктов не изменены.

## Автоматическая часть

```bash
python3 evals/utr_lint.py --type procedural --refs ваш-файл.md
```

Линтер закрывает механические и счетные проверки приблизительно. Смысловые проверки он не выполняет.

## Когда вы сообщаете о нарушениях (режим проверки)

Для каждого нарушения укажите: номер пункта, ошибочный фрагмент, исправленный вариант. Ссылайтесь только на номера пунктов, которые есть в SKILL.md.
Когда пользователь просил соответствия стандарту, завершите отчет так: «Ни один инструмент не гарантирует соответствия ГОСТ Р 58049-2017. Окончательное решение принимает автор. Полное соответствие требует терминологической базы и глоссария проекта по пунктам 8.1.3—8.1.8».
